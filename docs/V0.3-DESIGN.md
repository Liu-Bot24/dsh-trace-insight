# Trace Insight v0.3 设计基线

## 产品结果

Trace Insight 由两层协作完成：

1. 程序化分析持续读取 DSH 原始 Session Event Log，在每个关闭的 Turn 建立低成本、可重复的确定性检查点。
2. 模型分析在旁路调用中解释连续区间的决策链、根因和经验。它使用独立默认模型，也允许每个手动区间临时换用其他模型。

模型调用不创建 Agent、不追加原会话事件，也不改变工作区。

## 深模块与接口

### Coverage Planner Module

小接口：输入原始事件、已覆盖水位和策略，输出下一段连续区间与触发原因。

内部负责：

- 按 Turn/Seq 建立连续覆盖；
- 在压缩输入达到上限前切段；
- 大 Turn 在事件边界安全拆分；
- 识别高风险、终止、累计 Turn、累计事件和静默期触发；
- 模型失败时保持水位不变。
- 对完整序列化证据包执行硬字符预算，而不只统计 evidence 数组。

### Semantic Model Adapter

小接口：列出 DSH 已注册模型；使用指定 provider/model 分析一份压缩证据包。

内部负责：

- 旁路调用 `ctx.llm.stream()`；
- 将轨迹视为不可信数据，抵抗轨迹内提示注入；
- 发送前脱敏常见凭证；
- 组装流式输出、用量和终止状态；
- 解析结构化 JSON，无法解析时保留原始文本而不伪造字段。

### Analysis History Store

小接口：读取/更新全局设置；原子读取/更新一个 Session 的分析历史。

内部负责：

- 每个 Session 一个文件，避免单一巨型数据库文件；
- 串行化同一 Session 的并发写入；
- 临时文件加原子替换；
- 损坏数据拒绝覆盖；
- 保存不可变程序化检查点和模型运行记录。
- 保存每次运行的设置快照、持久化退避状态、后台诊断与崩溃中断状态。

### Trace Insight Service

这是 Host 对 Client 的唯一业务 Seam。RPC 只暴露：

- 读取当前解读和历史；
- 列出模型；
- 更新默认模型与自动策略；
- 对指定区间和指定模型执行手动分析；
- 导出原历史、分析历史或完整研究包。

事件订阅、调度、缓存、持久化、模型调用和错误恢复都留在模块内部。

## 连续覆盖策略

程序化检查点在每个 `turn/end` 后生成。模型层默认满足任一条件时触发：

- 未覆盖区间出现高严重度确定性诊断；
- Turn 以 error、blocked、aborted 或 interrupted 结束；
- 累积 4 个已关闭 Turn；
- 累积 160 个原始事件；
- 压缩输入接近 22,000 字符；
- 最后一个 Turn 结束后静默 90 秒。

这些阈值可在界面调整。

模型主覆盖链只接受从 `coveredThroughSeq + 1` 开始的成功运行。失败、取消和格式错误均作为历史记录保留，但不越过缺口。长历史被拆成连续区间；下一段只接收上一段的有限连续性摘要和新压缩增量，不重复发送全部原始日志。

进入“解读”标签只读取现有模型历史并补齐免费的程序化检查点；它不调用、不排队模型，也不重置静默计时器。自动调度由 Host Turn 事件、设置变更和启动恢复驱动。

只有被实时 `turn/end` 明确纳入自动分析的 Session，才会在 DSH 重启后按原 Turn 结束时间恢复静默期限。遗留 `running` 记录先转为 `ANALYSIS_INTERRUPTED`，再进入持久化退避。安装前从未索引的旧 Session 首次查看只建立程序化索引，不因随后重启而自动付费；模型回填由用户按 Turn/Seq 区间手动启动，后续新 Turn 才会完成自动纳入。

所有自动失败共享同一持久化、路由/配置感知的指数退避，页面轮询、静默触发、设置触发和新 Turn 都不能绕过或丢失退避唤醒。不可重试的模型响应立即暂停，其他错误最多自动付费尝试 3 次；换模型或修改相关模型/输入设置后才按新配置重新评估。切换默认路由后会逐个恢复所有已纳入 Session，而不是只恢复当前页面。不同 Session 的外部模型调用通过 Host 级调度闸门全局串行，避免设置变更或启动恢复时并发突发。

## 手动运维语义

手动运行由四项组成：

- 起始 Turn/Seq；
- 结束 Turn/Seq；
- 本次 provider/model；
- 是否绕过相同输入、相同模型和相同分析器版本的缓存。

手动运行是补充版本，不覆盖旧结果，也不篡改自动主覆盖链。相同区间可以保留多个模型版本供人工比较；即使命中完全相同的缓存，也新增一条带来源运行 ID 的运维记录，而不是把旧记录冒充本次操作。

## 历史与导出

时间线同时展示：

- 程序化检查点；
- 自动模型检查点；
- 手动换模版本；
- 失败和待重试运行；
- Seq、Turn、时间戳、触发原因和模型路由。

导出格式：

- `raw`：DSH 原始 Session header、事件、surface 与谱系观察；
- `analysis`：全局设置、每次运行的设置快照、程序化检查点、模型运行、缓存来源、覆盖水位、后台诊断、失败/中断记录、失败时已生成文本与 usage/finish、退避/暂停状态和版本信息；
- `bundle`：同时包含 raw 与 analysis，供外部二阶分析。

## 界面方向

界面采用“取证时间线”而不是普通卡片仪表盘：左侧是一条按 Turn/时间推进的主轴，程序化和模型层使用不同节点；顶部覆盖轨显示两层各自到达的 Seq 和缺口。默认模型、自动策略、区间选择、换模运行和三种导出等运维控制集中在“设置”标签，不占用时间线阅读空间。

界面整体注册进 DSH 会话壳层的右侧检查器（`inspector` 槽位）：左边继续显示“对话/轨迹”，右边同步显示解读，可折叠、可自由拖拽调宽；未打补丁的旧 Host 回退为会话页的“解读”标签。窄屏时内部控件自动收成单列；所有控件提供键盘焦点，动画遵守 reduced-motion。

视觉使用深靛蓝表示确定性证据、玉绿色表示成功模型洞察、琥珀色表示未覆盖/待处理、红色表示失败。正文使用系统中文字体，Seq/模型路由使用等宽字体。
